Building Vector Embeddings
From Scratch

Using the phrase "machine learning" as our worked example — every equation shown

CH 01 Step 1 — Build a Vocabulary

Before any math happens, we need a vocabulary — a fixed list of every word the model knows. Each word gets a unique integer index. Let's say our tiny toy vocabulary has just 8 words:

IndexWordWhat it means (simplified)
0machinea mechanical or computing device
1learningacquiring knowledge or skill
2deepextending far down
3neuralrelating to nerves / neurons
4datafacts and statistics
5modela mathematical representation
6trainto teach a system using examples
7vectora list of numbers

Vocab size V = 8. In real life (e.g. BERT), V = 30,522 words. The math is identical — just bigger.

CH 02 Step 2 — One-Hot Encoding

Computers can't process the string "machine". We first convert every word into a one-hot vector: a list of zeros with a single 1 in the position matching the word's index.

Definition — One-Hot Vector
x = one_hot(i) = vector of length V,
where x[j] = 1 if j == i, else 0

CH 03 Step 3 — The Embedding Matrix W

The embedding model keeps a giant matrix W (called the embedding table). Its shape is V × D where V = vocab size and D = embedding dimension.

In our toy example: V=8, D=4. In real BERT: V=30522, D=768. Every row in W is the embedding for one word.

Shape of Embedding Matrix
W ∈ ℝ^(V × D) = ℝ^(8 × 4)

Each row W[i] = embedding vector for word i
These values start random, then improve during training.

Here is our toy W matrix (randomly initialized values):

W (8×4 matrix) — rows = words, cols = embedding dimensions

Now to get the embedding for "machine", we multiply the one-hot vector by W. But since the one-hot has a single 1 at index 0, this is literally just picking row 0:

Embedding Lookup = Matrix Multiply
e = x · W

// x is shape (1×8) one-hot, W is shape (8×4)
// result e is shape (1×4) — the embedding!

emachine = [1,0,0,0,0,0,0,0] · W = row0 of W
CH 04 Step 4 — The Dot Product in Detail

Let's compute the actual dot product step by step. The embedding for "machine" is row 0 of W. Each output dimension d is:

General Formula
e[d] = Σj=0V-1 x[j] · W[j,d]

// Since x is one-hot with 1 at index i, all terms zero out except j=i
e[d] = 1 · W[i,d] = W[i,d]

CH 05 Step 5 — Activation Function (ReLU)

In a deeper network, after each layer's dot products, we apply an activation function. The simplest is ReLU (Rectified Linear Unit):

ReLU Definition
ReLU(z) = max(0, z)

// Negative values → 0. Positive values → unchanged.
// This adds "non-linearity" — lets the network learn complex patterns

Applied to "machine"'s raw embedding [0.52, -0.31, 0.18, -0.74]:

💡 Why ReLU? Without activation functions, stacking layers does nothing — they collapse into one. ReLU "switches neurons on/off," letting the model learn which features matter for a given input.
CH 06 Step 6 — Cosine Similarity: Measuring Meaning Distance

Once we have two vectors, how do we measure how similar their meanings are? We use cosine similarity — the cosine of the angle between the two vectors in high-dimensional space.

Cosine Similarity Formula
cos(θ) = A·B / (||A|| × ||B||)

A·B = Σ A[i] × B[i] // dot product
||A|| = √(Σ A[i]²) // magnitude / length

Range: −1 (opposite) → 0 (unrelated) → +1 (identical)

After training, let's say these are the learned embeddings (3D for clarity):

"machine" vs "learning" SIMILAR

machine = [0.8, 0.5, 0.3]
learning = [0.7, 0.6, 0.2]
A·B = 0.8×0.7 + 0.5×0.6 + 0.3×0.2
= 0.56 + 0.30 + 0.06 = 0.92
||A|| = √(0.64+0.25+0.09) = √0.98 ≈ 0.99
||B|| = √(0.49+0.36+0.04) = √0.89 ≈ 0.94
cos(θ) = 0.92 / (0.99 × 0.94) ≈ 0.989 ✓

"machine" vs "pizza" DIFFERENT

machine = [0.8, 0.5, 0.3]
pizza = [-0.1, 0.9, -0.7]
A·B = 0.8×(−0.1) + 0.5×0.9 + 0.3×(−0.7)
= −0.08 + 0.45 − 0.21 = 0.16
||A|| ≈ 0.99
||B|| = √(0.01+0.81+0.49) = √1.31 ≈ 1.14
cos(θ) = 0.16 / (0.99 × 1.14) ≈ 0.142 ✗

CH 07 Step 7 — How the Model Actually Learns (Training)

The matrix W starts with random numbers. Training updates W so that similar words land near each other. Here's the exact process, step by step:

1

Feed a training pair

Example: "machine" and "learning" appear together in text → they should be similar. Feed both words into the model.

2

Compute embeddings → cosine similarity

Lookup both vectors from W. Compute cos(θ) between them. If they're random initially, cos(θ) ≈ some arbitrary value.

3

Compute the Loss

We want cos(θ) = 1.0 (identical direction). The loss measures how far off we are:

Contrastive Loss (simplified)
// For a POSITIVE pair (words that should be similar):
Loss = 1 − cos(eA, eB)

// If cos=0.3 (bad): Loss = 1 − 0.3 = 0.7 ← big penalty
// If cos=0.95 (good): Loss = 1 − 0.95 = 0.05 ← small penalty

// For a NEGATIVE pair (words that should differ):
Loss = max(0, cos(eA, eB) − margin)
4

Backpropagation — compute gradients

Calculate ∂Loss/∂W — how much each number in W contributed to the error. Calculus chain rule is applied through every layer.

Gradient Descent Update Rule
W ← W − η · ∂Loss/∂W

η = learning rate (e.g. 0.001)
// Tiny step in the direction that reduces loss

Example: if W[0,2] = 0.18, gradient = 0.4, η = 0.01:
W[0,2] ← 0.18 − 0.01 × 0.4 = 0.176
5

Repeat billions of times

Do this for billions of word pairs across all of Wikipedia, books, the web. After training, W's rows are the final embedding vectors — now rich with semantic meaning.

Let's trace the complete forward pass for the phrase "machine learning" end to end:

Complete Forward Pass
// 1. Tokenize
"machine learning" → tokens: ["machine", "learning"]

// 2. Index lookup
"machine" → index 0
"learning" → index 1

// 3. One-hot vectors (V=8)
x_machine = [1,0,0,0,0,0,0,0]
x_learning = [0,1,0,0,0,0,0,0]

e_learning = W[1] = [0.48, −0.27, 0.22, −0.69]

// 5. Pool: mean of both vectors (for phrase embedding)
e_phrase = (e_machine + e_learning) / 2
= [0.50, −0.29, 0.20, −0.715]
